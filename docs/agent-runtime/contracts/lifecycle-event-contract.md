# Lifecycle Event Contract

## Envelope

Every event contains:

- schema version;
- event ID;
- event kind;
- event time and ingestion time;
- run, stack, service, and agent IDs when applicable;
- context generation, disclosure, snippet, tool, trace, span, Incus operation, and artifact correlation IDs when applicable;
- source component and version;
- severity;
- sensitivity;
- attributes;
- canonical evidence references;
- optional error object.

Unknown event kinds MAY be stored, but product projections must not assign semantics without a registered schema.

## Event families

Initial kind prefixes:

- <code>run.*</code>;
- <code>stack.*</code>;
- <code>package.*</code>;
- <code>context.*</code>;
- <code>disclosure.*</code>;
- <code>loadout.*</code>;
- <code>runtime.*</code>;
- <code>incus.*</code>;
- <code>agent.*</code>;
- <code>prompt.*</code>;
- <code>skill.*</code>;
- <code>snippet.*</code>;
- <code>tool.*</code>;
- <code>command.*</code>;
- <code>approval.*</code>;
- <code>claim.*</code>;
- <code>research.*</code>;
- <code>artifact.*</code>;
- <code>verification.*</code>;
- <code>cleanup.*</code>.

## Required state events

Every durable run-state transition produces an event with previous state, next state, state version, reason, actor, and timestamp.

## Observation versus assertion

Events distinguish:

- directly observed runtime facts;
- orchestrator decisions;
- agent claims;
- user approvals or assertions;
- inferred correlations.

An agent claim event does not create a verified graph edge without evidence resolution.

## Delivery

Events are persisted through Cortex-compatible ingestion with bounded batching, backpressure, retries, shutdown drain, and idempotency. The run orchestrator must not block indefinitely on non-critical telemetry, but critical state transitions require durable publication or an explicit degraded state.

## Redaction

Attribute keys and values pass existing secret and sensitive-field redaction. Raw prompts, transcripts, logs, and tool parameters are stored only under policy and are referenced from events rather than duplicated by default.

## Ordering

Events carry per-run sequence numbers where generated by Soma. Cross-source event time may be skewed; ingestion time and Cortex clock-skew analysis remain available. Consumers must not infer total global order from timestamps alone.
