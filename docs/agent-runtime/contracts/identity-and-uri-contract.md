# Identity and URI Contract

## IDs

Runtime IDs are opaque strings generated by Soma. Callers MUST NOT derive semantics from their internal encoding.

Required ID kinds:

- <code>stack_id</code>;
- <code>service_id</code>;
- <code>run_id</code>;
- <code>agent_id</code>;
- <code>runtime_instance_id</code>;
- <code>context_id</code> and <code>context_generation_id</code>;
- <code>disclosure_request_id</code> and <code>disclosure_decision_id</code>;
- <code>snippet_id</code> and <code>snippet_execution_id</code>;
- <code>claim_id</code>;
- <code>research_question_id</code> and <code>job_id</code>;
- <code>artifact_id</code>;
- <code>lifecycle_event_id</code>.

IDs MUST be unique within the Soma deployment. ULID is recommended for new runtime IDs because current Code Mode state already uses ULIDs for temporary and plan identities, but the public contract remains opaque.

## Canonical references

A <code>CanonicalRef</code> identifies a record in an authoritative store. It contains:

- scheme;
- authority or store;
- kind;
- identifier;
- optional revision or generation;
- optional fragment;
- content digest when available.

Examples:

~~~text
soma://run/01K...
soma://context/01K.../generation/2
axon://document/<id>@<generation>
cortex://observation/<id>
git://dinglebear-ai/soma/<commit>/crates/soma/application/src/app.rs
labby://upstream/cortex/tool/context
incus://project/default/instance/soma-investigator-01k
apm://package/microsoft/example@1.2.0
~~~

Schemes are logical identifiers. They do not imply direct network fetch.

## Content identity

Files, manifests, lockfiles, resolved definitions, materializations, and artifacts MUST use lowercase SHA-256 hex digests. A digest identifies bytes, not semantic equivalence.

## Names

User-facing names use lowercase kebab-case. Names are mutable labels and MUST NOT replace IDs in durable relationships.

## Parent relationships

Child contexts, snippet executions, research questions, and lifecycle events MUST carry explicit parent IDs rather than encoding ancestry in names.

## Path identity

Host paths are deployment-local and MUST NOT be used as cross-host canonical identifiers. Run manifests MAY record host paths for audit while also carrying canonical references and container-relative paths.
